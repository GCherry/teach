Should I Build an MCP Server? Decision & Failure Checklist

Quick pre-build filter to avoid wrapping REST APIs or CLIs in unnecessary MCP ceremony—plus hardening rules proven in ytmix/internal/mcp/. Pair with Lesson 0002: The Hidden Costs of MCP.

1. Five-Gate Decision Scorecard

Gate Question Prefer HTTP REST / gRPC Prefer CLI (--json) Prefer MCP Server
1. Who is the caller? Deterministic app, web frontend (ytmix ui), or cron job. Human dev or coding agent with bash access. Multiple non-shell AI Hosts (desktop chat, IDE sidebars).
2. Discovery model? Static build-time contract / OpenAPI SDK. On-demand --help only when invoked. Runtime initialize + tools/list across unrelated Hosts.
3. Surface size? Any size (dozens/hundreds of routes). Large command trees with subcommands. Focused (<15 tools) to protect prompt context budget.
4. Streaming & binaries? Native SSE push + direct media/file HTTP streams. Local file paths + stdout progress. Short JSON responses; avoid giant inline blobs or high-frequency polling.
5. Guided UX & consent? Custom frontend UI handles confirmations. TTY flags (--dry-run, --yes). Server-authored Prompts + Host consent via ToolAnnotations.

2. MCP Cons & Hardening Checklist (From ytmix/internal/mcp/)

Context & Transport Hygiene

Prevent Bloat & Broken Pipes

  • Cap tool count & schema verbosity: Keep descriptions crisp; don't mirror 50 internal REST routes 1:1.
  • Use Resources for reference data: Put static catalogs (ytmix://presets, ytmix://themes) behind URIs instead of extra tool calls.
  • Stderr-only diagnostics: Never write logs or banners to stdout in stdio servers (server.go isolates diagnostics to ErrOut).
  • Bound message sizes: Enforce a max frame byte limit (16 MiB in server.go) so malformed streams cannot OOM the Host.
Safety & Async Trade-Offs

Defend Against Non-Deterministic Callers

  • Separate dry-run from writes: Expose read-only planning (plan_mix) separately from side effects (start_render).
  • Validate strictly on the server: Treat ToolAnnotations as Host UX hints only; use DisallowUnknownFields() (registry.go).
  • Expect indirect prompt injection: Treat external text returned in tool outputs (e.g., rawId3Title) as untrusted input.
  • Watch async polling cost: Long jobs (start_render → get_render_status) burn LLM turns; keep job payloads compact.
