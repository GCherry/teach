Lesson 0001 · Zone of Proximal Development: Gateway & Telemetry Foundations

The Agnostic Control Plane: Subscriptions, APIs, and Local Models

You already built the workflow brain of a software factory in chill-hq (Coordinator v2, six specialist Roles, Risk Tiers, and Merge Bar). Now we build the platform plane underneath it: one vendor-agnostic control plane that governs cost and captures unified usage across Google Antigravity, Claude Code subscriptions, metered APIs, and local models.

Mission Tie-In

In MISSION.md, your goal is two-fold: (1) upgrade chill-hq with observability + gateway routing, and (2) pitch an enterprise governance model to leadership. This lesson gives you the foundational architecture pattern that solves both without locking you into one IDE or model vendor.

1. The Trap Most Teams Fall Into

When engineering leaders ask "How do we track token usage and put credit limits per user?", the knee-jerk answer is: "Put every coding tool behind a single API proxy like LiteLLM."

That works cleanly for pay-as-you-go APIs and local Ollama servers—and then immediately collides with reality:

  • Flat-rate subscription harnesses don't bill through your API key. Harnesses like Google Antigravity or a Claude Code Pro/Max seat authenticate via vendor OAuth against flat-rate or seat-pooled entitlements. Forcing them through a pay-per-token API proxy breaks subscription billing or fails auth altogether.
  • Conversely, relying only on vendor subscription portals breaks factory automation. Headless CI reviewers, Slack-triggered "Minion" workers (Stripe Engineering), and local Ollama models cannot run on an individual engineer's OAuth session—and vendor dashboards won't let you tag requests with your internal issue_number or Coordinator Role.
Architectural Principle

Never confuse the billing rail with the observability schema. A true agnostic Software Factory separates how tokens are transported & billed (two paths) from how usage is attributed & measured (one canonical schema).

2. The Solution: Dual-Path Control Plane

Instead of forcing every tool through one bottleneck, route workloads through two complementary ingestion paths that emit the exact same canonical factory_event/v1 record (modeled on OpenTelemetry GenAI Semantic Conventions).

Figure 1: Both billing worlds converge at the canonical factory_event/v1 schema rather than forcing subscriptions through a metered proxy.

Path 1: The AI Gateway Proxy (Metered APIs + Local Models)

An AI Gateway such as LiteLLM Proxy exposes one unified OpenAI/Anthropic-compatible endpoint in front of commercial providers and local runtimes (Ollama, vLLM, LM Studio). Three capabilities make it essential for your leadership pitch and for chill-hq:

  1. Virtual Keys + Rolling USD Credit Caps: Instead of handing developers raw Anthropic or OpenAI keys, every engineer and headless CI agent gets a Virtual Key mapped to user_id and team_id with a max_budget (e.g., $20/day or $250/month) plus TPM/RPM loop guards. Credits normalize across models—1M local tokens cost $0, 1M Haiku/Flash tokens cost cents, and 1M frontier reasoning tokens debit accordingly.
  2. Role-Tiered Model Routing: Your chill-hq Coordinator already splits work into Planner, Engineering, Reviewer, Docs, Release, and Retro. Through a gateway, you can map logical model aliases like factory-architect (frontier) vs. factory-utility (local Qwen/Llama or Flash) without hardcoding model IDs into skills.
  3. Custom Attribution Headers: Harnesses and scripts pass headers like x-factory-role, x-factory-repo, and x-factory-branch so the gateway logs exactly which repo and Coordinator role spent each token.

Path 2: Harness Collector Hooks (Antigravity & Claude Code Subscriptions)

When you use Google Antigravity today—or add a Claude Code subscription next—you still need visibility into tokens, tool calls, session duration, and PR outcomes without double-paying API rates.

  • Claude Code: Supports native OpenTelemetry export via CLAUDE_CODE_ENABLE_TELEMETRY=1, streaming metrics (claude_code.token.usage, claude_code.cost.usage, active time) straight to your local or enterprise OTLP collector.
  • Google Antigravity & Local Logs: Writes structured session artifacts (such as transcript.jsonl) locally. A lightweight collector script triggered at PR handoff or by chill-hq's Retro role can extract token/tool summaries, attach current git repo/branch/PR metadata, and emit the same factory_event/v1 record with billing_mode: "subscription".
